## 服务证据的边界

只读 observer 后加于运行中，早期无覆盖；已捕获 429 是正证据，未捕获不等于没有。旧 observer 未保留 Retry-After 的单位，新版明确记录秒／毫秒。重试头是服务要求的等待值，不能把求和机械解释成精确损失时间。

Munkres 复测的终末错误明确为 token 限流（limit=100000），但窗口定义、缓存 token 的计费方式和与 64K 输出上限的关系尚未核实。成功响应也曾报告超过 100000 个输入 token，所以不能断言存在简单的 100000-token 请求长度上限。账号标识和原始错误体不入 Git。

成功请求中的重试等待包含在 Alaya 的 effect elapsed 中；最终抛出 provider transient 错误的请求没有形成 answered 事件，其等待不计入日志累计时间。因此 Munkres 的 1519.540 秒仅是已记录 effect 总时间，不是实际总等待时间。运行被正式 stop 后评分，未利用该差异追加预算。

后续从 Greenery 复测开始串行运行，仍满足协议的最多两条并行约束；记录此运行条件变化，不宣称串行已消除限流。
