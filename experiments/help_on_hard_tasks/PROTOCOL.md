# 困难任务中的主动求助：探索性预试验

2026-10-07，在首条模型响应前固定。目标：先找出 DeepSeek 在给定预算下不能稳定独立完成、且有实质障碍的任务，再观察在全新运行中提供求助工具和既定指导是否会出现有用的问题。导师的“困难会不会触发求助”是待检验假设，不预设答案。

## 有效困难与环境验收

所有初始公开 Impl、Spec、Proof、Joint、Bundle、Harness 模块显式编译。空白 `Test` 中的求值因实现为 sorry 而失败是预期现象，不能把默认 build 的这种失败算为模型能力问题。模板缺失标识符、超时评分、服务拒绝、格式提取失败分别记录；如果它们主导结果，不纳入“有效困难”条件。运行中真实代码／证明错误是可审阅的任务结果。

求助工程探针固定提问、固定答复、继续写文件、独立评分；零模型调用，不算自然求助。评分微型任务必须同时通过 0/1 空答案拒绝和 1/1 正确答案接受。

## 全新运行及提示

每次从同题原始空白工作区重新创建独立数据目录，不复用旧轨迹或模型缓存。准备只调用 new/call，不调用 resume；检查初始配置与无样本日志。首次实际采样后，从该样本的请求记录审计第一条为 system、第二条为任务，模型、工具和 guidance 匹配，此前没有 reply 或 tell。

启动偏差：Primepy 首次准备误将新版 `--samples 0` 当作零采样；该参数实际表示无限，因而已启动首条预定 solo 轨迹。其模型、初始提示和 1800 秒上限正确；保留为第一条参照运行，事后核验实际请求，记录响应上限未强制执行，不能称作完整按协议启动。其余运行在首采样前已修正 runner。失败但未采样的准备目录保留，不计独立试次，不补偿性追加 Primepy。

help 组在首次 system 中沿用已确认的高收益、可重复求助、收尾前实际检查时间的指导，公开说明回答者是 AI 助手代理。另明确本轮没有额外的后续解题预算，以免 stock checkpoint 文案让模型误以为以后一定续跑。solo 只用于筛题，不能把它与 help 的差值解释为提示或答复的独立因果效应。

没有中途强制“现在求助”，不因零求助追加试次。问题需由模型通过 ask_user 产生。自然问题的回复在原轨迹继续，累计时间和响应数不重置；预算耗尽后的问题保留但不追加运行。

## 助手答复

回答者是本助手，不是真人受试者。读取本次问题和该时点的公开工作区后，提供具体问题所需的最小可操作建议，可包括局部引理、API、诊断或模型主动询问的算法建议。不得读取 trusted 实现、评分工作区或以往筛选的详细解法来充当答案；研究者知道筛选得分与障碍分类，不能声称盲答。

代码在独立公开副本验证，记录 Lean 版本、命令、退出码和覆盖范围；未验证部分明确标注。不得直接替模型编辑工作区。记录 answer_begin、发送时间、来源、依据、验证局限及原文散列；保留不正确或未被采用的建议，不改答重跑。允许按同一规则回答后续问题。

## 评分、输出和解释

每条运行结束后才独立评分，未结束的预算终点先 stop。筛选的评分仅用于选择新题；不反馈给模型。评分镜像固定 trusted 任务和评分脚本，通过 TAP 返回结果。

报告逐条通过数／总数、是否完整、求助次数、首次求助时间、停止原因、截断、样本数、模型时间、答复等待与处理时间。人工审阅问题是否可回答、建议是否采用／核验、局部障碍是否解决，以及之后的障碍。不能由“未问”推断内在动机；不能从前后进展直接断言答复的因果效果。

输出简明中文结果与 2–3 个可见轨迹例子；对实际问题制作后续真人研究的问题材料、背景分层问卷和答复记录表。当前不招募、不发消息；真人参与数为 0。原始请求、模型推理、密钥、完整工作区及 trusted 资料留在本机 scratch；Git 仅保存实验代码、协议和审阅证据。
